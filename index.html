Case study — current work

Multi-agent enterprise assistant

In progress · 2026 · Architecture & implementation

Three separate questions arrive at an internal help desk in the same sentence: what does the policy document say, has anyone hit this error before, and what do the numbers actually show. Each needs a different retrieval strategy, and a single RAG pipeline over one index answers all three badly.

So the assistant routes instead of retrieving. A supervisor classifies intent and hands the question to a sub-agent; every sub-agent reaches its data through an MCP server rather than through embedded client code. That boundary is the design decision the whole thing rests on — tools stay swappable, and a new data source becomes a new MCP server rather than a change to agent logic.

What the pieces do

  • Knowledge Agent — answers from written material, calling two MCP servers depending on whether the question is about documented policy or a problem someone has already solved
  • Knowledge Assistant MCP — semantic retrieval over a vector database holding a full dump of the company's SharePoint documents
  • Support Assistant MCP — retrieval over historically resolved support tickets, pre-processed to pull out root cause, resolution and problem statement, then indexed in Databricks Mosaic AI. Unstructured ticket threads become a searchable body of prior fixes
  • Data Discovery Agent — answers quantitative questions against governed tables in Unity Catalog, using the Databricks Genie MCP to turn the question into a query

Case study — enterprise platform

Agentic data structuring platform

CPG client · 2024 — 2026 · Led development

Enterprise source data arrives inconsistent, deeply nested and undocumented. Mapping it into a usable schema is manual work that scales with the number of sources, and it is the step that quietly sets the pace of every downstream analysis.

The platform reads the source, proposes a structure, and gives the data modelling team a recommendation to accept or correct — rather than trying to be right unattended. Keeping a human at the decision point is what made it adoptable; the agents do the reading, the modellers keep the judgement.

Outcomes

  • LangGraph architecture with in-memory vector stores cut manual data processing by 70%
  • Data consistency and accuracy improved 50%, shortening stakeholder decision cycles
  • Extended to complex nested .txt, .json and .csv sources, widening coverage across enterprise systems
  • LLM-based recommendations added for modelling decisions on nested structures, with an interactive application so teams act on them in place

Getting it into production

  • 11 FastAPI microservices carrying the engine into client platforms — versioning, OAuth 2.0, modular design, structured logging and exception handling as defaults
  • Two major releases delivered with high availability; functional and integration testing in Postman, concurrency and throughput validated with JMeter
  • Automated cloud deployment through Azure DevOps CI/CD
  • Client satisfaction up 40% on the back of stable delivery
